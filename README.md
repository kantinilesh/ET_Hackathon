# qAifin — AI-Native Financial Intelligence Platform

> *"Where Financial Decisions Explain Themselves."*

qAifin is a full-stack AI-powered financial intelligence platform built for modern fintech operations. It combines traditional ML with Explainable AI, Retrieval-Augmented Generation (RAG), agentic workflows, and computer vision — packaged into a single, audit-ready platform.

## Overview

Most fintech platforms produce outputs — risk scores, fraud flags, claim decisions — without explaining *why*. qAifin solves this by wrapping every AI decision in a plain-language narrative that users, analysts, and regulators can actually read and audit.

The platform is built around five core problems in fintech:

| Problem | qAifin's Answer |
|---|---|
| Opaque risk scores | SHAP-powered Risk Narrator |
| Fragmented financial data | Unified Financial Copilot (LLM Agent) |
| Manual document research | RAG-based Research Analyst |
| Slow insurance claims | CV + NLP Claim Automation |
| Compliance overhead | Auto-generated Regulatory Reports |

## Features

### 1. Financial Copilot
A conversational AI agent that answers plain-English questions about a user's finances. It aggregates data from the risk service, transaction database, personalization engine, and live market feeds to produce a single, context-aware response.

Example queries:
- *"Am I financially safe this month?"*
- *"Why did my risk score increase?"*
- *"Should I increase my SIP this quarter?"*

### 2. Risk Decision Narrator
Every risk score is generated by an XGBoost/LightGBM model and explained using SHAP values. The platform converts raw SHAP output into a structured JSON payload, which an LLM then narrates into a human-readable explanation — suitable for the end user, an auditor, or a regulator.

### 3. Autonomous Research Analyst
Users upload financial documents (earnings reports, SEC filings, RBI bulletins, news articles). The system embeds and indexes them into a vector store, then uses RAG to answer queries with source-cited, confidence-scored responses.

### 4. Smart Insurance Claims
Users submit a damage photo and policy document. A computer vision model assesses damage severity; an NLP pipeline parses the policy for relevant clauses; a rule + ML hybrid calculates eligibility. The output is a fully explained claim decision with direct policy references.

### 5. Fraud Detection
An anomaly detection model monitors transactions in near real-time. Each alert includes a confidence score and a behavioural comparison against the user's own baseline — not just a static threshold breach.

### 6. Compliance Report Generator
Admins can auto-generate monthly risk summaries, model drift audits, and fraud trend reports. The LLM converts raw logs and model outputs into formatted, RBI-compliant PDF reports.

### GenAI Orchestration

The platform uses an agentic architecture with a master orchestrator coordinating specialised sub-agents:

- **Risk Agent** — queries risk models, fetches SHAP values, writes explanations
- **Investment Agent** — pulls market data, analyses portfolio, generates recommendations
- **Compliance Agent** — monitors logs, detects anomalies, writes audit notes
- **Research Agent** — handles document ingestion, embedding, retrieval, and citation

## Getting Started

### Prerequisites

- Python 3.11+
- Node.js 20+
- Docker & Docker Compose
- PostgreSQL 15
- Redis 7

### Installation

```bash
# Clone the repository
git clone https://github.com/your-org/qaifin.git
cd qaifin

# Start all services with Docker Compose
docker-compose up --build

# Or run services individually

# Backend services
cd services/risk_intelligence
pip install -r requirements.txt
uvicorn main:app --reload --port 8001

cd services/research
pip install -r requirements.txt
uvicorn main:app --reload --port 8002

# Frontend
cd frontend
npm install
npm run dev
```

### Environment Variables

Create a `.env` file in the root directory:

```env
# Database
DATABASE_URL=postgresql://user:password@localhost:5432/qaifin
REDIS_URL=redis://localhost:6379

# AI / LLM
OPENAI_API_KEY=your_key_here
# OR for open-source:
OLLAMA_BASE_URL=http://localhost:11434

# Vector Store
PINECONE_API_KEY=your_key_here
PINECONE_ENVIRONMENT=us-east-1

# MLflow
MLFLOW_TRACKING_URI=http://localhost:5000

# Auth
JWT_SECRET=your_secret_here
JWT_ALGORITHM=HS256
```

## Module Breakdown

### Risk Intelligence Service

The risk pipeline runs on every significant user action and on a nightly batch:

```
Raw Features → Feature Store → XGBoost Model → Risk Score
                                     ↓
                              SHAP Explainer
                                     ↓
                         Structured JSON (feature contributions)
                                     ↓
                              LLM Narrator
                                     ↓
                     Plain-language explanation + audit log
```

Risk factors evaluated:
- Transaction velocity and value anomalies
- Liquidity ratio (rolling 30-day)
- Credit utilization and payment history
- Savings consistency score
- Debt-to-income ratio
- Market exposure concentration

### Research Engine (RAG Pipeline)

```
Document Upload → Text Extraction → Chunking → Embedding
                                                    ↓
                                             Vector Store (FAISS)
                                                    ↓
User Query → Query Embedding → Similarity Search → Top-K Chunks
                                                    ↓
                                         Reranking (cross-encoder)
                                                    ↓
                                    LLM Synthesis + Source Citations
```

Supported document types: PDF, DOCX, TXT, HTML

### Insurance Automation

```
Damage Photo → CV Model → Severity Classification (A/B/C/D)
Policy PDF   → NLP Parser → Relevant Clause Extraction
                                        ↓
                          Rule Engine + ML Hybrid
                                        ↓
                     Eligibility Calculation + Rationale
```

## Data Flow

### Example: User asks "Am I financially safe this month?"

```
1. Frontend  →  API Gateway (auth check + rate limit)
2. Gateway   →  GenAI Orchestrator
3. Orchestrator activates:
      ├── Risk Agent       → Risk Intelligence Service → Risk Score + SHAP
      ├── Tx Agent         → Transaction DB → Last 30 days summary
      ├── Market Agent     → Market Data API → Portfolio valuation
      └── Personalization  → Feature Store → User spending profile
4. Orchestrator aggregates structured context
5. Context → LLM (with guardrails) → Narrative response
6. Response → Frontend (with audit log entry)
```

## Security & Compliance

- **Authentication**: OAuth2 + JWT with refresh token rotation
- **Authorization**: Role-Based Access Control (User / Analyst / Admin)
- **Encryption**: AES-256 at rest, TLS 1.3 in transit
- **Input Validation**: All endpoints validate against Pydantic schemas
- **Rate Limiting**: Per-user and per-IP limits enforced at gateway
- **Audit Logging**: Every model decision is logged with inputs, outputs, and SHAP values
- **GenAI Guardrails**:
  - Prompt injection detection
  - Restricted financial advice filters (platform provides analysis, not regulated advice)
  - Model output validation against confidence thresholds
  - Hallucination detection via fact-checking layer
- **Compliance**: Designed to align with RBI guidelines on AI in financial services

## Monitoring & Observability

| Tool | Purpose |
|---|---|
| Prometheus | Metrics collection (API latency, error rates, model inference time) |
| Grafana | Dashboards for system health and ML performance |
| Elasticsearch | Centralized log aggregation |
| Kibana | Log search and visualization |
| MLflow | Model experiment tracking, versioning, drift detection |

Key metrics monitored:
- API p95/p99 latency
- Model accuracy drift (weekly evaluation against labelled holdout)
- Data freshness (staleness alerts if feature store > 1h old)
- Fraud model false positive rate
- LLM response confidence scores
